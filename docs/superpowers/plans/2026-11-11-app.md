# App Implementation Plan (plan 3 of 3)

**Status:** implemented on feat/app (Tasks 1–9, Task 10 Steps 3–5); manual checks Steps 1–2 pending.

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The iOS app: SwiftUI screens for start, lobby, table, showdown and ranking on top of `PokerCore`/`PokerNet`, so a whole tournament night runs without the chip case.

**Architecture:** A new package target `PokerSession` holds everything the app needs that is worth testing: display values derived from `GameState` (dealer hints, quick picks, all-in check), save files (host snapshot, guest seat ticket) and `TableSession`, an `@Observable` main-actor object that runs `TableHost` + its own loopback `TableClient` (host) or a `TableClient` (guest). The Xcode project `App/` is generated by XcodeGen and contains only SwiftUI views that read a `TableSession` and send `Command`s through it.

**Tech Stack:** Swift 6, SwiftUI (iOS 17), Observation, Swift Testing, XcodeGen (build tool only). No external dependencies.

**Spec:** `docs/superpowers/specs/2026-11-11-pokerchipcase-design.md` · Protocol: `docs/PROTOCOL.md`

**Previous:** plan 1 `PokerCore`, plan 2 `PokerNet` (both merged).

**Deviation from the spec (approved by the user on 2026-11-11):** tournament settings (presets) are chosen when the table is created, not in the lobby. `PokerCore` has no command to change the config after `HostSnapshot.newTable`, and adding one would change protocol v1.

## Review Focus

1. **Guest phone locked mid-hand:** iOS drops the connection; on return the guest reconnects with its token, keeps its seat and sees the current state → `guestReconnectsAfterDrop` (Task 3).
2. **Host phone locked:** iOS tears down the listener; on return `appBecameActive()` restarts it on the same port and guests get back in → `appBecameActiveRestartsListener` (Task 3).
3. **Host app killed mid-hand:** relaunch → "Resume game" → same phase, same seats, guests reconnect → `resumeAfterHostCrash` (Task 3), Bonjour part manually in Task 10.
4. **Guest app killed:** relaunch → "Rejoin …" takes the old seat back instead of joining as a new player → `rejoinWithTicketKeepsSeat` (Task 3).
5. **Calling with your last chips is an all-in too:** it asks for confirmation like the all-in button → `lastChipsCountAsAllIn` (Task 1).

- [ ] **Step 4: Implement** in `Display.swift`

`dealerHint`: `.betting` and no seat has `acted` → by `street`: preflop `.dealHand`, flop `.dealFlop`, turn `.dealTurn`, river `.dealRiver`; `.showdown` with `street != .river` → `.dealRest`; otherwise nil.
`quickPicks`: from `legalActions(for:)`; no `minRaiseTo`/`maxRaiseTo` → `[]`. With `base = potTotal + callAmount` (the pot after calling): half pot = `currentBet + base / 2`, pot = `currentBet + base`, each clamped to `minRaiseTo...maxRaiseTo`; all-in = `maxRaiseTo`. Drop half pot/pot when equal to `maxRaiseTo` or to an earlier pick.
`commitsAllChips`: `allIn` → true; `call` → `currentBet - roundBet >= stack`; `raiseTo(x)` → `x >= roundBet + stack`; otherwise false. Unknown player → false.

  public enum ConnectionStatus: Equatable, Sendable { case connecting, connected, reconnecting, failed(ClientFailure) }

  @MainActor @Observable public final class TableSession {
      public let tableName: String
      public let code: TableCode
      public private(set) var state: GameState?
      public private(set) var me: PlayerID?
      public private(set) var connection: ConnectionStatus      // starts as .connecting
      public private(set) var isSending: Bool
      /// Reason of the last rejected command; cleared by the next `state` and by `send`.
      public private(set) var rejection: Rejection?
      public var isHost: Bool { get }                           // this device runs the TableHost
      public var legalActions: LegalActions? { get }            // me's legal actions; nil when it is not my turn
      /// Dealer of the hand or host: may resolve the showdown and start the next hand.
      public var canRunHand: Bool { get }

      /// Hosts `snapshot` (new or resumed) and joins it over loopback with the host token.
      public static func host(_ snapshot: HostSnapshot, saveFile: SaveFile<HostSnapshot> = .host,
                              port: NWEndpoint.Port = .any) async throws -> TableSession
      public static func join(endpoint: NWEndpoint, tableName: String, code: TableCode, name: String,
                              token: String? = nil, ticketFile: SaveFile<SeatTicket> = .seat) async -> TableSession
      public func send(_ command: Command) async
      public func act(_ action: Action) async                   // send(.act(player: me, action:))
      /// Call when the scene becomes active: restarts the host listener iOS tore down.
      public func appBecameActive() async
      /// Disconnects; the host also stops the table. Deletes this device's save file.
      public func leave() async

      // internal, for tests
      let client: TableClient
      private(set) var tableHost: TableHost?
      private(set) var port: NWEndpoint.Port?
  }

- [ ] **Step 3: Implement**

`host(_:saveFile:port:)`: save the snapshot first (a crash in the lobby is resumable too); `TableHost(snapshot:onChange: { try? saveFile.save($0) })`; `start(port:)`; `TableClient(endpoint: .hostPort(host: "127.0.0.1", port: bound), code: snapshot.code, name: <host seat name>, token: snapshot.hostToken)`. `join`: a `TableClient` with the given values. Both start one main-actor `Task` that reads `client.events`, then `await client.connect()`.
Events: `.welcome` → `me`, `.connected`; a guest saves `SeatTicket(tableName:code:name:token: welcome.token)`. `.state` → `state`, `rejection = nil`. `.connectionLost` → `.reconnecting`. `.failed(f)` → `.failed(f)`; a guest deletes its ticket.
`send`: return if `isSending` (double tap); otherwise `isSending = true`, `rejection = nil`, await `client.send`; `.rejected(reason)` → `rejection = reason`; thrown errors are ignored because `connection` already shows the problem; `isSending = false` at the end.
`appBecameActive`: `try? await tableHost?.ensureListening()` with `// ponytail: if the old port is taken the table stays unreachable; restart on .any + new loopback client if that happens in practice`.
`leave`: `client.disconnect()`; host: `tableHost.stop()` then `saveFile.delete()`; guest: `ticketFile.delete()`.
