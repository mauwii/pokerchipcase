# DocC Docs and App Icon Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Publish a DocC site for the three libraries, with the wire protocol in it, on GitHub Pages, and give the app an icon with light, dark and tinted appearances.

**Architecture:** One DocC catalog per library. `xcodebuild docbuild` builds the three archives, `docc merge` joins them, and `docc process-archive transform-for-static-hosting` produces the site that `actions/deploy-pages` publishes from `main`. The icon is three hand-written SVGs, rendered once by hand to 1024 px PNGs in an asset catalog that xcodegen picks up.

**Tech Stack:** Swift-DocC (Xcode toolchain), GitHub Actions and Pages, xcodegen, `rsvg-convert` (librsvg) and `sips` for the icon.

**Spec:** [docs/superpowers/specs/2026-11-13-docc-icon.md](../specs/2026-11-13-docc-icon.md)

## Global Constraints

- One PR, on branch `docs/docc-icon`.
- No new package dependency: no `swift-docc-plugin`. No secrets.
- Every action is GitHub-owned and pinned by commit SHA with the version in a comment:
  - `actions/checkout@3d3c42e5aac5ba805825da76410c181273ba90b1 # v7.0.1`
  - `actions/upload-pages-artifact@fc324d3547104276b827a68afc52ff2a11cc49c9 # v5.0.0`
  - `actions/deploy-pages@368f82528645a54fb793d4d04e342629a3f51346 # v5.0.1`
- Workflow top level: `permissions: contents: read`. Checkout uses `persist-credentials: false`. Every job has `timeout-minutes`, as in `ci.yml`.
- Site URL: `https://mauwii.github.io/pokerchipcase/documentation/`, hosting base path `pokerchipcase`.
- Files under `docs/superpowers/` keep the old path `docs/PROTOCOL.md`.
- Code, comments, docs and commits in English. Conventional Commits.
- `pre-commit run --all-files`, `swift test` and the app build pass after every task.

## Review Focus

1. A ``` ``Symbol`` ``` link in `Protocol.md` or an overview that names a non-existent symbol renders as plain text with only a warning. The build has to fail instead, so it uses `--warnings-as-errors` (Task 1 locally, Task 3 in CI).
2. A wrong hosting base path gives a site whose HTML loads but whose CSS and JS return 404 under `/pokerchipcase/`. Task 3 checks the generated `index.html` for the prefix.
3. If the light icon has an alpha channel, App Store Connect rejects the upload. If the dark and tinted icons have no alpha, iOS shows a square instead of its backdrop. Task 4 checks `hasAlpha` for all three.
4. A PR run must never request `pages: write` or `id-token: write`. Only the `deploy` job on `push` has them. Task 3 checks this with actionlint and zizmor, and by reading the `if:` conditions.
5. A link to `docs/PROTOCOL.md` left outside `docs/superpowers/` is a dead link on GitHub. Task 1 checks this with `grep`.

  5. `actions/upload-pages-artifact` with `path: .build/site`, `if: github.event_name == 'push'`
- Job `deploy`:
  - `if: github.event_name == 'push'`, `needs: build`, `runs-on: ubuntu-latest`, `timeout-minutes: 10`
  - `environment: name: github-pages, url: ${{ steps.deployment.outputs.page_url }}`
  - `permissions: pages: write, id-token: write`
  - one step `actions/deploy-pages` with `id: deployment`
- Add `concurrency: group: pages, cancel-in-progress: false` on the `deploy` job only. Two pushes then deploy in order, and PR runs never queue behind a deploy.

### Task 4: App icon

**Files:**

- Create: `App/Icon/icon.svg`, `App/Icon/icon-dark.svg`, `App/Icon/icon-tinted.svg`
- Create: `App/Sources/Assets.xcassets/Contents.json`, `App/Sources/Assets.xcassets/AppIcon.appiconset/Contents.json`, and three PNGs in that set: `icon.png`, `icon-dark.png`, `icon-tinted.png`
- Modify: `App/project.yml` (target `settings.base`)

- [ ] **Step 1: Write the three SVGs**

- `viewBox="0 0 100 100"`, `width`/`height` 1024. Use the exact shapes and colors from the spec table, in this order: background, chip body, edge inserts, center, spade.
- `icon.svg` has the felt background. `icon-dark.svg` has no background element. `icon-tinted.svg` has no background, chip body and center `#8a8a8a`, spade fill `#222`, white stays white.
- Each file starts with a comment that names its render command, as in Step 2: `rsvg-convert -w 1024 -h 1024 <this file> -o <png>` (`brew install librsvg`). `icon.svg` also names the two `sips` commands that remove the alpha channel. No README.

- [ ] **Step 2: Render**

```sh
brew install librsvg
S=App/Sources/Assets.xcassets/AppIcon.appiconset
mkdir -p $S
rsvg-convert -w 1024 -h 1024 App/Icon/icon.svg -o $S/icon.png
rsvg-convert -w 1024 -h 1024 App/Icon/icon-dark.svg -o $S/icon-dark.png
rsvg-convert -w 1024 -h 1024 App/Icon/icon-tinted.svg -o $S/icon-tinted.png
T=$(mktemp -d)
sips -s format jpeg -s formatOptions 100 $S/icon.png --out $T/i.jpg
sips -s format png $T/i.jpg --out $S/icon.png
```

- [ ] **Step 3: Check the alpha channels**

Run: `sips -g hasAlpha -g pixelWidth App/Sources/Assets.xcassets/AppIcon.appiconset/*.png`
Expected: `icon.png` hasAlpha `no`, the other two `yes`. All three are 1024 wide.

Look at the three PNGs with the Read tool. They have to match the spec: a red chip, 8 white edge inserts, a dashed center ring and a black spade with a white outline.

- [ ] **Step 4: Write the catalog JSON**

- `Assets.xcassets/Contents.json`: `{"info":{"author":"xcode","version":1}}`.
- `AppIcon.appiconset/Contents.json`: three `images` entries, each `"idiom":"universal","platform":"ios","size":"1024x1024"` with its `filename`. The dark entry adds `"appearances":[{"appearance":"luminosity","value":"dark"}]`. The tinted entry adds `"appearances":[{"appearance":"luminosity","value":"tinted"}]`. End with the same `info` block.

- [ ] **Step 5: Set the icon name in `App/project.yml`**

Add `ASSETCATALOG_COMPILER_APPICON_NAME: AppIcon` under `targets.PokerChipCase.settings.base`.

- [ ] **Step 6: Build**

Run the app build from AGENTS.md.
Expected: success with no asset catalog warning. Check with `find .build/app -name 'Assets.car' -path '*PokerChipCase.app*'`: the file exists.

- [ ] **Step 7: Lint and commit**

Run: `pre-commit run --all-files`
Expected: passes. `check-added-large-files` allows 500 KB per file. A larger PNG gets `pngcrush` or a smaller compression level, not a raised limit.
