# PokerNet Implementation Plan (Plan 2 von 3)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Target `PokerNet` im Package `PokerChipCase`: Host-Server und Client, die `PokerCore`-Spiele verschlüsselt über das lokale Netz (WLAN oder Peer-to-Peer) spielen, mit Bonjour-Discovery, Reconnect per Token und wiederherstellbarem Host-Zustand.

**Architecture:** `MessageChannel` kapselt eine `NWConnection` (TCP + TLS-PSK + WebSocket) als `AsyncThrowingStream`. `TableHost` (actor) besitzt den `HostSnapshot` (Game + Token-Tabelle), nimmt Verbindungen an, übersetzt `hello`/`command` in `Game.apply` und sendet `ack` und `state`. `TableClient` (actor) verbindet sich, schickt Befehle mit `stateVersion`, wartet auf das `ack` und verbindet sich nach Abbrüchen selbst neu. Das Host-Gerät nutzt ebenfalls `TableClient` über Loopback mit dem Host-Token.

**Tech Stack:** Swift 6, `Network.framework` (`NWListener`, `NWConnection`, `NWBrowser`, `NWProtocolWebSocket`, `NWProtocolTLS`), `CryptoKit` (HKDF), Swift Testing. Keine externen Abhängigkeiten.

**Spec:** `docs/superpowers/specs/2026-11-11-pokerchipcase-design.md` · Protokoll: `docs/PROTOCOL.md`

**Vorgänger:** Plan 1 `PokerCore` (gemergt). **Folgeplan:** Plan 3 App.

## Global Constraints

- Plattformen bleiben `.iOS(.v17)`, `.macOS(.v14)`; Tests laufen mit `swift test` auf macOS ohne iPhone
- Keine externen Dependencies
- Transport exakt wie `docs/PROTOCOL.md`: TLS 1.2 (min und max), Cipher Suite `TLS_PSK_WITH_AES_128_GCM_SHA256`, PSK = HKDF-SHA256(ikm: Code-UTF-8, salt: `pokerchipcase-v1`, info: `pokerchipcase-psk`, 32 Byte), PSK-Identity `pokerchipcase`, WebSocket-Textframes, Bonjour-Typ `Wire.serviceType`
- `includePeerToPeer = true`, `allowLocalEndpointReuse = true`, TCP-Keepalive an (`keepaliveIdle = 2`)
- WebSocket `maximumMessageSize = 1_048_576`, `autoReplyPing = true`
- Tests verbinden über Loopback `NWEndpoint.hostPort(host: "127.0.0.1", port:)`; nur Task 5 nutzt Bonjour
- Jeder asynchrone Test wartet höchstens 5 s auf ein Ereignis (Helper `EventRecorder`), Suite-Trait `.timeLimit(.minutes(1))`
- **Stop-Bedingung:** Lässt sich TLS-PSK mit dem installierten SDK nicht herstellen (Task 1), nicht auf eine andere Verschlüsselung ausweichen, sondern anhalten und fragen. Das ist eine Sicherheitsentscheidung.

## Review Focus

1. **Host-Neustart aus gespeichertem Snapshot:** Clients verbinden sich mit ihrem Token neu und behalten ihren Sitz → `clientReconnectsAfterHostRestart` (Task 4).
2. **Gleiches Token verbindet sich zweimal** (alte Verbindung noch nicht als tot erkannt): die neue gewinnt, die alte wird geschlossen → `secondConnectionWithSameTokenReplacesFirst` (Task 2).
3. **Falscher Tisch-Code:** sofort `failed(.wrongCode)`, keine Endlos-Wiederholung → `wrongCodeFailsWithoutRetry` (Task 4).
4. **Kaputte Nachricht:** Host antwortet `malformed`, die Verbindung und alle anderen bleiben bestehen → `malformedMessageGetsErrorAndConnectionStays` (Task 3).
5. **Senden ohne Verbindung:** wirft sofort `ClientError.notConnected`, hängt nicht → `sendWhileDisconnectedThrows` (Task 4).

  ```swift
  enum ChannelEvent: Equatable, Sendable { case ready, message(Data) }
  enum ChannelError: Error, Equatable { case handshakeFailed, closed }
  /// ponytail: @unchecked Sendable, NWConnection ist auf `queue` beschränkt
  final class MessageChannel: @unchecked Sendable {

  ```
  Test-Helper in `Helpers.swift`:
  ```swift
  /// Sammelt Ereignisse eines Streams; `first(where:)` wartet höchstens `timeout`.
  actor EventRecorder<Event: Sendable> {
      /// Liest `stream` in einem eigenen Task mit; funktioniert für AsyncStream und AsyncThrowingStream.
      init<S: AsyncSequence & Sendable>(_ stream: S) where S.Element == Event
      func first(timeout: Duration = .seconds(5), where: @Sendable (Event) -> Bool) async throws -> Event
      /// Wartet auf das Stream-Ende; liefert den Fehler, mit dem er endete (nil = sauber beendet).
      func waitForEnd(timeout: Duration = .seconds(5)) async throws -> (any Error)?
  }
  struct TimeoutError: Error {}
  /// NWListener mit PSK-Parametern; jede neue Verbindung wird zum Echo-Kanal.
  func startEchoListener(code: TableCode) async throws -> (NWListener, NWEndpoint.Port)
  func loopback(_ port: NWEndpoint.Port) -> NWEndpoint
  ```

`HostSnapshot.newTable`: Host-ID und Host-Token sind je `UUID().uuidString`; `Game(hostID:hostName:config:)`.
`TableHost`: `NWListener(using: PSK.parameters(code:), on: port)`; `start` wartet auf `.ready` und gibt den Port zurück, `.failed` → wirft. Pro Verbindung eine `UUID`, ein `MessageChannel` und ein `Task`, der dessen `events` liest und `handle(_:from:)` im Actor aufruft. Zustand: `channels: [UUID: MessageChannel]`, `bound: [UUID: PlayerID]`.
`hello`-Regeln, in dieser Reihenfolge:
1. `protocolVersion != Wire.version` → `.error("versionMismatch")`, Kanal schließen
2. Token bekannt → an diesen Spieler binden; eine andere Verbindung desselben Spielers schließen und entfernen
3. sonst neuer Spieler: `PlayerID = UUID().uuidString`, `game.apply(.join(player:name:), by: hostID, at: Date())`; `.tableFull` → `"tableFull"`, `.invalidPhase` → `"gameInProgress"` (jeweils `.error`, Kanal schließen); bei Erfolg neues Token speichern, `onChange(snapshot)`
4. `.welcome(Welcome(player:token:))` an diese Verbindung, dann `.state` an **alle** gebundenen Verbindungen

Server-Nachrichten bekommen jeweils eine neue `UUID` als Umschlag-`id`. Kanal-Ende → Verbindung entfernen (der Sitz bleibt). `stop()` beendet Listener und alle Kanäle.

- [ ] **Step 3: Implementieren**

`connect`: `MessageChannel(to:code:)`; auf `.ready` sendet der Client `hello(protocolVersion: Wire.version, name:, token:)`. Server-Nachrichten:
- `welcome` → Token übernehmen, verbunden = true, `.welcome`
- `state` → `lastState`, `.state`
- `ack` → wartende Continuation zu `ack.id` fortsetzen
- `error` mit Code `versionMismatch` / `tableFull` / `gameInProgress` → `.failed(...)`, keine Wiederholung; andere Codes ignorieren

Kanal-Ende: endet er mit `ChannelError.handshakeFailed` → `.failed(.wrongCode)`, Ende. Sonst `.connectionLost` (nur, wenn vorher verbunden), alle wartenden `send` mit `ClientError.connectionLost` fortsetzen, nach `retryDelay` neu verbinden, bis `disconnect()`.
`send`: nicht verbunden → `ClientError.notConnected`; sonst `id = UUID()`, Continuation unter `id` merken, `.command(CommandRequest(command:, stateVersion: lastState?.version ?? 0))` senden, auf `ack` warten und `result` zurückgeben.
