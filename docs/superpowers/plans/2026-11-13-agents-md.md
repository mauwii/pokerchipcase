# AGENTS.md / CLAUDE.md Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Give coding agents that clone this public repo the project rules behind the published specs and plans, in one `AGENTS.md` that `CLAUDE.md` imports.

**Architecture:** All content lives in `AGENTS.md` (read by Codex and other agents). `CLAUDE.md` holds the single line `@AGENTS.md`, which Claude Code expands as an import. No duplication of `README.md`: link it instead.

**Tech Stack:** Markdown. Repo: Swift 6.0 package (`PokerCore`, `PokerNet`, `PokerSession`) plus a SwiftUI iOS 17 app generated by XcodeGen.

**Spec:** the chat decision of 2026-11-13 (no spec file):

- Add `AGENTS.md` + `CLAUDE.md` containing `@AGENTS.md`.
- Content: build/test commands, module layout, conventions, superpowers workflow.
- Exclude: the maintainer's personal model/effort routing, merge policy, secrets policy, anything already in `README.md`.
- Target length 30–50 lines.

## Global Constraints

- English only (repo is open source).
- `AGENTS.md` ≤ 50 lines, `CLAUDE.md` exactly one line: `@AGENTS.md`.
- Every command in `AGENTS.md` copied verbatim from `README.md` or `.github/workflows/ci.yml`; no invented commands.
- Write it with the `mattpocock-skills:writing-for-agents` skill loaded.
- Branch `docs/agents-md` from `main`, not from `chore/ponytail-cleanup`.

## Review Focus

- A fresh agent runs only what `AGENTS.md` says: every command must work from the repo root as written.
- Facts drift: module list must match `Package.swift` targets exactly (`PokerCore`, `PokerNet` → `PokerCore`, `PokerSession` → `PokerCore` + `PokerNet`).
- An agent edits `App/PokerChipCase.xcodeproj` or `App/Info.plist`: `AGENTS.md` must say they are generated, edit `App/project.yml`.
- An agent commits `.superpowers/` or `App/Config/Local.xcconfig`: `AGENTS.md` must say both are local and gitignored.
- Personal maintainer rules leak in (model routing, auto-merge, Device Hub): reviewer greps for them.

- [ ] **Step 2: Write `AGENTS.md`** with these sections and facts (wording is the implementer's):

1. **Project** — one line, link `README.md` for the full description. Play money only.
2. **Commands**
   - Package tests (macOS, no device): `swift test`
   - App build, exactly as CI does it:

     ```sh
     xcodegen generate --spec App/project.yml
     xcodebuild build -project App/PokerChipCase.xcodeproj -scheme PokerChipCase -destination 'generic/platform=iOS Simulator' -derivedDataPath .build/app CODE_SIGNING_ALLOWED=NO -quiet
     ```

   - Both must pass before a PR; CI runs both.
3. **Layout**
   - `Sources/PokerCore` — game rules, pots, commands, wire types; no dependencies.
   - `Sources/PokerNet` — networking, depends on `PokerCore`.
   - `Sources/PokerSession` — session state and save file, depends on `PokerCore` + `PokerNet`.
   - `App/Sources` — SwiftUI app; no unit tests, tested manually in simulators.
   - `Tests/<Target>Tests` — Swift Testing, one test target per library.
   - `docs/PROTOCOL.md` — wire protocol; update it in the same PR as any wire-format change.
4. **Rules**
   - Edit `App/project.yml`, never `App/PokerChipCase.xcodeproj` or `App/Info.plist` (generated, gitignored).
   - `App/Config/Local.xcconfig` is per-developer, gitignored, never commit it.
   - Swift 6 language mode, strict concurrency.
   - English for code, comments, docs, commits.
   - Conventional Commits with optional scope, e.g. `fix(app): …`, `refactor: …`, `docs: …`.
5. **Planning workflow**
   - Design specs: `docs/superpowers/specs/YYYY-MM-DD-<topic>.md`.
   - Implementation plans: `docs/superpowers/plans/YYYY-MM-DD-<topic>.md`, committed before implementation.
   - `.superpowers/` is local run state, gitignored, never commit it.
