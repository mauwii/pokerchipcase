# PokerChipCase Protocol (version 1)

This document describes everything a compatible client (for example an Android app) needs to join a PokerChipCase table. The types in `Sources/PokerCore/` (for example `ClientMessage`, `ServerMessage` and `GameState`) and the golden tests in `Tests/PokerCoreTests/WireTests.swift` are authoritative.

## Transport

| | |
|---|---|
| Discovery | Bonjour/mDNS, service type `_pokerchipcase._tcp`, instance name = table name |
| Connection | TCP with TLS; inside, one message per line: UTF-8 JSON terminated by `\n` (0x0A), at most 1 MiB per line |
| TLS | TLS 1.2, pre-shared key, cipher suite `TLS_PSK_WITH_AES_128_GCM_SHA256` |
| PSK | HKDF-SHA256: input = 4-digit table code (UTF-8), salt = `pokerchipcase-v1` (UTF-8), info = `pokerchipcase-psk` (UTF-8), 32-byte output |
| PSK identity | `pokerchipcase` (UTF-8) |
| PSK test vector | code `4711` → `67a659eb4579867f3873c0e9311b75f65b3d6d0b7c0c7cdc7687d0fb78f423f2` (hex) |
| Peer-to-peer | iOS additionally uses AWDL (`includePeerToPeer`); other platforms use the shared Wi-Fi |

A wrong table code makes the TLS handshake fail: the host cannot verify the client's `Finished` and sends a `bad_record_mac` alert. JSON is encoded compactly and therefore never contains a raw newline. A peer that receives a longer line drops the connection.

## Envelope

Every message, in both directions:

```json
{"id":"<UUID>","payload":<payload>,"type":"<type>","v":1}
```

- `v` – protocol version. Messages with a different version are rejected.
- `id` – UUID with hyphens, generated by the sender. iOS writes upper case; receivers compare case-insensitively.
- `type` – determines the shape of `payload`.
- Dates are milliseconds since 1970-01-01 UTC, as a number that may have a fractional part (parse as a double).
- Durations (`duration`, `pausedRemaining`) are seconds, as a number that may have a fractional part.
- Empty lines are ignored.

### Encoding of enums with associated values

`Command`, `Action` and `AckResult` are encoded as an object with exactly one key – the case name. Its value is an object with the labeled fields, or `{}` for cases without values:

```json
{"act":{"action":{"raiseTo":{"amount":60}},"player":"B"}}
{"fold":{}}
```

Enums without values (`Phase`, `Street`, `Rejection`) are plain strings.

## Client → Host

### `hello` – join or reconnect

```json
{"id":"00000000-0000-0000-0000-000000000001","payload":{"name":"Anna"},"type":"hello","v":1}
```

Send `hello` exactly once per connection, as the first message. The host closes a connection that has not completed the TLS handshake and `hello` within 10 s. `payload.token` (optional) is the token from an earlier `welcome`; with it the client takes its seat back after a disconnect. An unknown token counts as a new join. If a token connects a second time, the host sends the older connection `replaced` and closes it. A second `hello` on the same connection is answered with `malformed`.

### `command` – every game command

```json
{"id":"00000000-0000-0000-0000-000000000001","payload":{"command":{"act":{"action":{"raiseTo":{"amount":60}},"player":"B"}},"stateVersion":7},"type":"command","v":1}
```

`stateVersion` is `version` from the last `state` received. If it no longer matches the host's, the command is rejected with `staleState`. This discards double taps that arrive after the state has changed.

| Command | Fields | Who may send it |
|---|---|---|
| `join` | `player`, `name` | host only (the host issues it itself after `hello`) |
| `removePlayer` | `player` | host, not for itself |
| `arrangeSeats` | `order` (all player IDs) | host, lobby only |
| `startTournament` | `button` | host, at least 2 players |
| `act` | `player`, `action` | the player when it is their turn; the host additionally `fold`/`check` for others |
| `resolveShowdown` | `winners`: one list of player IDs per pot, in the same order as `state.pots`; each list non-empty, no duplicates, only IDs from `eligible` | dealer of the hand or host |
| `startNextHand` | – | dealer of the hand or host |
| `pauseClock`, `resumeClock` | – | host |
| `undo` | – | host |

Actions (`action`): `fold`, `check`, `call`, `raiseTo` with `amount` (total bet in this betting round; a bet if nobody has bet yet), `allIn`.

### Deriving legal actions

`state` does not contain a list of legal actions. For the player to act (`seats[toActIndex]`, called `s` below):

- `toCall = max(0, currentBet − s.roundBet)`
- **Check** is allowed if `toCall == 0`; otherwise **call** for `min(toCall, s.stack)` chips.
- `allInTo = s.roundBet + s.stack`
- **Raise** is allowed if `s.mayRaise` and `allInTo > currentBet`. Then `raiseTo.amount` lies between `min(currentBet + lastRaiseSize, allInTo)` and `allInTo`.
- `raiseTo` with `amount == allInTo` and `allIn` are always equivalent, even below the minimum raise. An all-in that goes above `currentBet` still requires `mayRaise`.
- **Fold** is always allowed.

## Host → Client

### `welcome` – reply to `hello`

```json
{"id":"…","payload":{"player":"B","token":"…"},"type":"welcome","v":1}
```

Keep the token secret and store it for reconnects.

### `ack` – reply to a `command`

```json
{"id":"00000000-0000-0000-0000-000000000001","payload":{"id":"00000000-0000-0000-0000-000000000001","result":{"rejected":{"reason":"notYourTurn"}}},"type":"ack","v":1}
```

`payload.id` is the `id` of the `command` being answered. Every `command` gets exactly one answer: an `ack`, or an `error` whose envelope `id` equals the command's `id` (see below). `hello` gets no `ack`; it gets `welcome` + `state`, or `error`. `result` is `{"ok":{}}` or `{"rejected":{"reason":"<Rejection>"}}` (see `Rejection`).

Reasons: `notHost`, `notDealer`, `notYourTurn`, `invalidPhase`, `illegalAction`, `invalidAmount`, `unknownPlayer`, `duplicatePlayer`, `tableFull`, `tooFewPlayers`, `invalidConfig`, `invalidShowdown`, `nothingToUndo`, `staleState`.

### `state` – complete table state

The payload is a `GameState`. Sent to all clients after every change. The most important fields of `payload`:

| Field | Meaning |
|---|---|
| `phase` | `lobby`, `betting`, `showdown`, `handComplete`, `finished` |
| `street` | `preflop`, `flop`, `turn`, `river` – last street reached |
| `seats[]` | in table order: `id`, `name`, `stack`, `roundBet`, `handBet`, `folded`, `allIn`, `acted`, `mayRaise`, `stackAtHandStart`, `eliminatedRank` (absent while still playing) |
| `buttonIndex` | index of the dealer in `seats` |
| `toActIndex` | index of the player to act (absent when nobody is to act) |
| `currentBet`, `lastRaiseSize` | highest bet of the round; minimum raise = `currentBet + lastRaiseSize` |
| `pots[]` | showdown only: `amount`, `eligible` (player IDs) |
| `clock` | `levelIndex`, `levelEndsAt` (date) or `pausedRemaining` (seconds) |
| `config` | `startingStack`, `levels[]` with `smallBlind`, `bigBlind`, `duration` |
| `version` | increases with every change; send it back as `stateVersion` in `command` |
| `hostID`, `handNumber` | |

Clients only display what the last `state` says and never change it themselves.

### `error`

```json
{"id":"…","payload":"versionMismatch","type":"error","v":1}
```

`payload` is a code; the app translates it into text. If the error answers a message whose envelope header could be read, the error's envelope `id` equals that message's `id`, so a client waiting for an `ack` can treat it as the answer.

| Code | Meaning | Connection |
|---|---|---|
| `versionMismatch` | `v` does not match | closed |
| `tableFull` | already 10 players | closed |
| `gameInProgress` | tournament running, new players can no longer join (reconnecting with a token still works) | closed |
| `helloRequired` | `command` before `hello` | stays open |
| `malformed` | message could not be read, or a second `hello` | stays open |
| `removed` | the player was removed from the table, in the lobby or mid-game (or their join was undone); the token is no longer valid | closed |
| `tableClosed` | the host ended the table; sent to every open connection before the host stops listening | closed |
| `replaced` | another connection took the seat with the same token (e.g. the player's second device) | closed |

## Flow

```text
Client                          Host
  | -- TLS-PSK handshake ------> |
  | -- hello ------------------> |
  | <------------------ welcome  |
  | <-------------------- state  |
  | -- command ----------------> |
  | <-------------------- state  |   (to everyone)
  | <---------------------- ack  |
```

On success the host sends the new `state` before the `ack`, so a client that waits for the `ack` already knows the new `version`.

## Versions

If the format changes incompatibly, `v` increases. A receiver treats any message with a different `v` as `versionMismatch` and stops retrying.

## Recommendations for clients

- Enable TCP keepalive (the iOS app uses 2 s idle, 2 s interval, 3 probes) so a vanished host is noticed within seconds.
- If no answer to a `command` arrives within 10 s, drop the connection and reconnect with the token.
- If a connection attempt has not reached `welcome` within 10 s, drop it and try again. A Bonjour resolve or TLS handshake can hang without ever reporting an error.
- After `versionMismatch`, `tableFull`, `gameInProgress`, `removed`, `tableClosed` or `replaced`, do not reconnect automatically.
- Any other `error` before `welcome` answers your `hello`, so the host cannot serve this client (for example an older host that answers `malformed` to a newer `hello`). Stop and treat it like `versionMismatch` instead of waiting for a `welcome` that never comes.
- Treat a `bad_record_mac` alert during the TLS handshake as a wrong code (do not retry). Retry every other failure, before or after the handshake: a host that is suspended or shuts down mid-handshake ends the connection with a reset or another TLS error.
- Resolve the Bonjour service to an address before the TLS connection. Apple's Network.framework retries a failed handshake on a service endpoint forever instead of reporting it, so a wrong code would never fail. The iOS app resolves with a plain TCP connection, which the host sees as one extra connection that ends before TLS.
- The cipher suite is plain TLS-PSK, which not every TLS stack offers by default (on Android, check the platform stack; BouncyCastle `bctls` supports it).

## Security

The protocol is built for a home game among friends, not for hostile networks:

- Plain PSK has no forward secrecy. Anyone who records one handshake can brute-force the 4-digit code offline and then decrypt that traffic.
- Everyone at the table knows the code. A player who records another player's traffic can read that player's token and take over their seat.
- The code mainly prevents joining the wrong table by accident and keeps casual observers out.
